**详情**：
- `Exchange` 两腿写完后在同一事务里读回 entries 校验：卖出腿必须让 holder 的源币恰好变动 `-Quantity`，买入腿让目标币恰好变动 `+TargetAmount`，两腿都不得碰对方币种；净额口径与 holder 账单一致（role-bearing 分类、`core.SignedAmount`）。不符返回 `ErrInvalidInput` 整体回滚。宿主把两腿都配成 `fx_buy` 不再能双向加余额。
- `FundingUID` 定义为「对该 holder 源币有用户侧分录的 journal uid」（充值 journal；用 booking 的宿主传其 `JournalUID`）。事务开头、加锁前只读核验：不存在 / 他人 / 他币种均 `ErrInvalidInput`；原 uid 重放仍为 no-op。文档与示例同步改为传 journal uid。
- `ConversionQuote.Validate` 用报价自身字段重跑 `FixedRate.Convert`，`TargetAmount` 必须恰好相等；撒谎报价在 journal 写入时即被拒。
- `GET /holder/transactions`：journal 的用户侧 holder 数 ≠ 1 时 `quotes` 置空并返回 `quotes_omitted: true`（新必填字段，openapi / React schema / 两皮肤 `quotesOmittedLabel` 同步）；被隐去的报价不解码，共享 journal 上的损坏报价不再让整页报错。SQL 用相关子查询避免整表扫描，页成本闸通过。

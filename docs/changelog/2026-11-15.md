# Changelog - 2026-11-15

## 测试基础设施：单一 PostgreSQL，去掉 Docker / testcontainers / 第二集群

**类型**：test/docs
**概述**：完整测试套件只连一个 PostgreSQL（`DATABASE_URL`，未设置时默认本机共享实例 `postgres://dev:dev@127.0.0.1:5432/postgres`），不再探测 Docker、不再起容器、不再要求第二集群。生产迁移 SQL 与 `postgres.Migrate` / `postgres.NewMigrationSource` 不变。

**详情**：
- `internal/postgrestest`：删除 testcontainers 容器与 `SetupIsolatedRawDB` / `system_identifier` 双集群校验；每个测试仍建独立库 `ledger_test_<pid>_<n>` 并在 `t.Cleanup` 删除；服务器不可达直接失败（F-9 不变），只有 `-short` 跳过。
- 全量 down→up 回滚重放（`TestMigrations_FullDownChainAndReapply`）在同一集群继续跑：新增测试专用 `NewRoleRewritingMigrationSource`，把迁移中的 `ledger_owner` / `ledger_app` / `ledger_ro` 改写成私有的 `ledger_test_<pid>_<n>_{owner,app,ro}`，down 链只删本测试的 role。测试额外断言：私有 role 在 Up 后存在、全量 Down 后消失、回滚库对象不归共享 role 所有也不授权给共享 role；普通 fixture 的 canary、表 owner、共享 `ledger_owner` OID 保持不变。`TestRoleRewritingSource_RenamesOnlyTheThreeRoles` 钉住改写只动这三个 role token。
- 新增 `internal/pgtestenv`（默认 URL、命名规则、运行锁、清理）与 `go run ./internal/pgtestenv/pgtestclean`：每个测试进程在整个生命周期内持有共享「运行锁」；清理以不等待方式独占拿到集群迁移锁（与 `Migrate` 同一 key，测试钉住）和运行锁后才动手，删除遗留测试库 / 测试 role，并在全集群无依赖时删除共享 `ledger_*` role；不碰其他名字。`make test` 收尾自动运行，`make test-clean-db` 可单独运行。
- 共享 role 不再被测试互相改写：登录 `ledger_app` / `ledger_ro` 的测试统一使用 `postgrestest.SharedRolePassword`；`TestRoleAttributeHardeningResetsPreExistingPrivileges` 改用私有 role 名，不再把共享 `ledger_app` 临时提成 SUPERUSER。
- `Makefile` 去掉 Docker 探测；`go.mod` 去掉 testcontainers、gofrs/flock 及其间接依赖；`docs/TESTING.md`、`CLAUDE.md`、`README.md` 同步。

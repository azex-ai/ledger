## [14:40] 安全评审修复：损坏数据错误码、币种代码字符集、报价编码收紧、锁并集补全

**类型**：fix/test/docs
**概述**：对 RateQuoter / Exchange / holder quotes 这轮改动做 T2 安全评审（security-reviewer + codex 第二意见 + scoped 再评审），一波修完全部 findings；两条需要契约裁决的 Major 未改，见文末。

**影响文件**：`core/errors.go`、`core/currency_code.go`（新）、`core/conversion.go`、`core/fixed_rate.go`、`core/interfaces.go`、`exchange.go`、`postgres/holder_store.go`、`pkg/bizcode/`、`pkg/httpx/`、`anchors/r2/internal/miniotest/miniotest.go`、`docs/BREAKING.md`、`docs/api.md`、`docs/api-surface.txt`。

**详情**：
- 读侧存量 `conversion_quotes` 解码失败不再报成 `10001 invalid input`：新增 `core.ErrCorruptData` → bizcode `19001`（新开 19000-19099 段：HTTP 500、不可重试，"已存数据违反写路径契约"）。整页仍 fail-closed，错误串改用 journal uid。
- 币种代码规则定为 `[A-Za-z0-9_.-]{1,64}`，`CurrencyInput.Validate`、`FixedRate.Validate`、`ConversionQuote.Validate` 共用；拒绝 RTL override、零宽字符、空白与控制字符（此前可原样渲染到 holder 账单）。`FixedRate.Version` 必须是合法 UTF-8 且无控制字符：`encoding/json` 把非法字节统一成 U+FFFD，两个不同的非法版本会编码成同一 payload，改值重试不会触发 `ErrConflict`。
- `DecodeConversionQuotes` 的三个金额字段只接受 JSON 字符串拼写（`EncodeConversionQuotes` 的产出），数字 / null / 缺失一律拒绝，避免同一报价两种拼写在幂等比较里不等价。
- `Exchange` 的 `LockForTemplates` 预取并集补上 `key+":settle"`，与 `preacquireBatchLocks` 的「后续用到的每个 key 都要先取」契约一致；新增查 `pg_locks` 的测试钉住。
- `Exchange` 文档写明：在 `RunInTx` clone 上调用没有 savepoint，宿主必须把错误从回调传出，吞掉即提交已写入的部分。
- MinIO 测试镜像改为 index digest 钉死（多架构）。
- 本日早些时候三个独立修复已入 main：分区再平衡测试按当前月计算窗口（日期炸弹）；baseline 迁移 `CREATE ROLE` 吞并发 `unique_violation` / `duplicate_object`（CI 共享集群角色竞态）；MinIO 夹具从已下架的 `minio/minio` 换到 `pgsty/minio`。

**未改、待拍板**（codex 第二意见 Major）：

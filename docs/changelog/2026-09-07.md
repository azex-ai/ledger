# Changelog - 2026-09-07

## [22:30] 汇率面向接口：RateQuoter port、库内 Exchange 原语、可解释的 holder 账单行

**类型**：feat/docs
**概述**：汇率存储归属拍板为"面向接口"——ledger 只定义一个 `core.RateQuoter` port、只消费已解析的 `FixedRate` 值、不存任何汇率配置；购买组合从示例提升为库内 `svc.Exchange`；holder 交易行携带报价，钱包能解释每笔扣费。

**影响文件**：`core/conversion.go`（新）、`core/journal.go`、`core/holder.go`、`exchange.go`（新）、`postgres/sql/queries/holder.sql` + sqlcgen、`postgres/holder_store.go`、`server/handler_holder.go`、`docs/openapi.yaml`、`examples/credits-topup/`、`web/packages/ledger-react/src/wallet/`、gaps / cookbook / api / frontend 文档、API surface 快照。

**详情**：
- `core.RateQuoter`：单方法 port；JSON 文件、宿主库表、外部行情源都是它的 adapter，`FixedRate.Version` 承载各自的版本或时间戳语义。ledger 不建汇率表、不做版本 UI（Aaron 2026-09-07 拍板）。
- `core.ConversionQuote` + `EncodeConversionQuotes/DecodeConversionQuotes`：`conversion_quotes` metadata 的规范编码（金额字符串、rounding 按名称如 `half_up`）；`JournalInput.Validate` 在写入时拒绝无法解码的值，读侧因此可把解码失败当错误而非容忍。`RoundingMode` 获得 `String/Parse/MarshalText`。
- `(*Service).Exchange`：Reserve → Settle → 双 FX 腿一个事务，`LockForTemplates` 先取全部锁的并集；两腿都记录报价与 `funding_uid`（充值来源），宿主对账靠它找"充值成功但没兑换"；在 `RunInTx` clone 上调用时加入宿主事务。重放同 key 同报价为 no-op，同 key 不同报价 / 来源为 `ErrConflict`，输出舍为零在写盘前拒绝。
- `GET /holder/transactions` 每行新增 `quotes`（source_code / source_quantity / rate / target_code / target_amount）；version、rounding、exponent 留在管理面，负向测试钉住不上 wire。
- `@azex/ledger-react` 两个皮肤在换算行下渲染"10000 input tokens × 0.002 + 2425 output tokens × 0.005"，共用 `describeQuotes` presenter 与 `unitLabels` 映射；数字原样渲染不再舍入。
- credits 示例：`pricing` 实现 `core.RateQuoter`，购买改走 `svc.Exchange` 并带入充值 journal uid。

**验证**：core / root（含 Exchange 5 项 PG 测试）/ server / postgres holder / credits 示例 race 测试、golangci-lint、sqlc diff、API surface 快照、README 门、web typecheck + codegen:check + vitest 全部通过（见计划文件验收段）。计划：[docs/plans/2026-09-07-rate-quoter-and-exchange.md](../plans/2026-09-07-rate-quoter-and-exchange.md)。

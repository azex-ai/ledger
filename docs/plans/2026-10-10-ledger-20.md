## 冻结契约

1. 冻结按 `(policy ID, currency ID)` 汇总，同币分类可抵消，异币不可抵消。金额目标 exponent 必须有限，Round / ConvertAt 保留有限负指数；Allocate 非负；工作精度界限与 Currency.Exponent 0..18 区分。
2. 当前 HTTP numeric holder 保持既有 Go int64 契约。React numeric SDK 明确只支持安全整数，发送前与解析响应后拒绝不安全 ID；UI strict parser 同步。完整 wire string 迁移另开版本，不在本次偷偷破坏 Go JSON。
3. 管理 cache scope 必须同时区分 backend 与非秘密身份，SSR 和浏览器显式复用稳定 scope；凭证绝不进入 query key。同 URL 的 BFF cookie 身份变化不一定能被 SDK 观察；宿主必须在身份边界变化时换非秘密 scope 或重挂拥有新 QueryClient 的 provider。SSR 与浏览器必须使用相同显式 scope；默认只能承诺可观察的实例/config 隔离，不承诺检测隐藏 cookie 切换。
4. 不新增数据库表或 migration。外部 quote、attestor、execution 均在 DB transaction 外。新的便捷门面不能声称强于原始事务/签名机制。

### Capture

新增 `(*Service).Capture(ctx, CaptureInput) (*CaptureResult, error)`。Input value fields：`ReservationUID string`、`Amount decimal.Decimal`（正数）、`IdempotencyKey string`、`TemplateCode string`（必填）、`Partial bool`、`ActorID int64`、`Source string`、`Metadata map[string]string`；Result：`ReservationUID string`、`JournalUID string`。所有导出字段 snake_case JSON。

新增窄接口 `core.ReservationReader.GetReservation(ctx, uid) (*core.Reservation, error)`，`Service.ReservationReader()` 暴露，postgres.ReserverStore 复用现有 sqlc.GetReservationByUID 和 row converter，无新增 SQL/migration，不扩张现有 Reserver 或 QueryProvider 以免破坏宿主替身。按 UID 非锁定预读仅用于获得 holder/currency，先获得全量 advisory locks，再由 settlement 在行锁内校验实际状态/期限/金额，不反转既有锁序。

从 reservation 读取 holder/currency；模板 amount 只有 `amount`；派生稳定 keys 为 base+`:settle` 与 base+`:charge`。metadata 绑定 reservation_uid、capture_mode 与 capture_template_code，拒绝冲突保留字段并复制宿主 map。预取全量有序锁，再 settlement + journal；模板必须让该 holder/currency 的 available 净减少 Amount，其他用户/币种或其他 role 变化拒绝。普通调用自建 tx，tx clone 加入调用者 tx，错误必须向上传播，无 savepoint。Partial 使用 SettlePartial；false 使用 Settle；零用量仍用 Release。普通 tx journal unsigned，签名示例另用已存在的 AuthorizeTemplate / PostAuthorized。

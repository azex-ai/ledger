## 改动与账务路径

- `capture.go` 添加带 snake_case JSON tags 的 `CaptureInput` / `CaptureResult`。金额先经过现有 `SettleInput.Validate`，拒绝非正数、不安全 decimal 表示、缺少必要 key 和保留 metadata。
- `core/reservation_reader.go` 是单方法窄接口，未扩张 `Reserver` 或 `QueryProvider`。`postgres/reservation_reader.go` 复用已有 `GetReservationByUID` 查询与转换器，支持 pool 和调用者事务，不增加 SQL、migration、rates 表或外部依赖。
- Capture 先无锁读取 reservation 的 holder / currency，再用 `LockForTemplates` 获取完整有序 advisory locks，包括派生的 `:settle` 与 `:charge` key。随后 settlement 在行锁下复核状态、到期时间、精度与余额，执行模板后检查实际 journal entries。
- 用户侧分录仅允许目标 holder、目标 currency 的 available classifications，净减必须精确等于 `Amount`。系统侧仅允许该 holder 的系统对手方；其他用户、币种以及用户侧 pending / locked / memo 均拒绝。模板唯一金额参数为 `amount`。
- 例如已有 1 USDC available 并 hold 1：一次 Capture 0.6 将 reservation 结算为 0.6，释放未使用的 0.4，同时产生 system settlement DR 0.6 / user available CR 0.6 的平衡 journal，最终 available 0.4、held 0。同一 key 重试返回原 journal UID，余额与 hold 不再改变。Partial Capture 0.3 则 available / held 都剩 0.7；后续按各次增量入账，Finalize 仅释放剩余 hold。
- Journal metadata 复制调用者 map 并绑定 `reservation_uid`、`capture_mode`、`capture_template_code`。这三个 key 禁止宿主传入，避免更换 reservation、模式或同分录模板时重用旧 journal。返回 journal UID 与 metadata 建立关联，不改写 reservation 的既有 `JournalUID`。
- README API Surface 添加两行；`docs/api-surface.txt` 通过现有 `UPDATE_API_SURFACE=1` 测试生成，新增 17 项导出符号，无删除或既有接口扩张。

## 失败、重试与边界

- 顶层 Service 自建 `RunInTx`，任一失败回滚 settlement、receipt、journal 与余额。调用者事务内直接加入现有事务，不创建 savepoint；调用者必须返回 Capture 错误。组合更多金融操作时，调用者须预先获取所有操作锁的并集。
- 保持先 settlement 后 journal 的冻结顺序。主控在 `f13d0ae` 记录的裁决允许模式切换提前被 `ErrInvalidTransition` 拒绝；不增加 replay 查询来统一成 `ErrConflict`。测试确认这类拒绝不会留下额外 hold / journal 变更。其余被测试的 amount、actor、source、metadata、template、reservation 变更均安全拒绝。
- 这是较窄的 Capture 便捷契约：带用户 memo 的 `fee_charge` 等模板也拒绝；宿主需要自行组合更复杂的计费 journal。主控已确认此限制及 `capture_template_code` 绑定，并授权 API 文档最小同步。
- 普通调用者事务路径中的 journal 与 reservation discharge claim 为 unsigned，即使配置 `WithAttestor`。需要 verifiable journal 时，沿用事务外 `AuthorizeTemplate`、事务内 `PostAuthorized` 的宿主组合；unsigned discharge 对 verified-balance gate 的保守 hold 持续至到期。Capture 不调用外部签名器或执行资金转移。
- Reservation 防止其他 reservation 超额占用，不能阻止绕过流程的 raw journal 消费。宿主仍须配置 account policies 并将消费路由到 reservation 流程。

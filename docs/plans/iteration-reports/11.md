输入为 Phase 0 及 Task 11 的 available 兑换契约；输出为 Exchange 两腿经济效果检查、真实 PostgreSQL 模板回归和范围单元测试。交由 root 做独立域评审、Codex 第二意见与串行集成。

## 契约

卖出腿的用户 available 净额必须为 `-Quantity`，买入腿必须为 `Quote.TargetAmount`，按每个分类的 `NormalSide` 计算，不能将 pending 或 locked 当作可用金额。其他用户分类必须逐 `(holder, currency, classification)` 净额为零；不同分类或不同 role 之间不可互相抵消。同一非 available 分类的精确净零分录不改变经济结果，仍允许。

每条腿只接受该腿 currency，以及目标 holder 与其 system counterpart；不能携带其他用户或第三种 currency 的分录。`classificationRoles(ctx, tx)` 保持原签名，供独立实现的 Capture 复用。Capture 的契约更窄，会拒绝非 available entry；两者不能混称同一种模板契约。

事务、union lock 顺序和 idempotency keys 不改变。普通调用失败会回滚完整 Exchange；加入宿主 `RunInTx` 的调用继续遵守既有无 savepoint 契约，宿主必须向上传播错误。

## 回归设计

- 12 个真实双分录模板：卖出/买入各覆盖 pending 替代、locked 替代、available 超扣/超发由 pending 抵消、pending 与 locked 抵消、两个 pending 分类抵消、memo 额外变化。
- 拒绝后检查 source/target available、自定义分类、held amount，以及 journals、entries、reservations、settlement receipts、checkpoints、rollup rows 全部回滚；随后同一 key 改用默认模板可完成兑换。
- 真实同一 pending 分类净零正例与重放；独立范围测试覆盖 debit/credit-normal available、多个 available 分类聚合、其他 holder/currency/counterpart 与未知分类。

## 结果与契约

`createLedgerClient` 的统一 async request 在 fetch 前校验请求 holder，在解码成功响应后、返回任何 data 前校验响应 holder。`createServerLedgerClient` 复用该 client，因此同样受保护。新增的 `holder-boundary.ts` 集中维护实际 DTO 的 holder 字段位置，不改变数字 HTTP wire 或 Go int64 范围。

仅接受 `Number.isSafeInteger`：范围为 `-9007199254740991` 到 `9007199254740991`。超过范围、非整数、NaN、Infinity 均拒绝。负 system holder 和 `0` 不在 SDK 额外禁用，由各 API 保留既有业务语义。原始 JSON 中相邻的 `9007199254740992`、`9007199254740993` 即使解析成相同 JS number，也都拒绝；负方向同样检查。不会向调用方返回已取整的伪造 holder。

失败通过原有 Promise 路径 reject，错误为 `RangeError`，`name=UnsafeHolderError`、`code=LEDGER_UNSAFE_HOLDER`，`location` 指出请求或响应中的字段位置。所有 16 类无效请求测试直接断言返回 Promise rejection；校验与 URL 构造在 async request 内，没有把这些无效请求改成同步 throw。请求失败发生在 fetch 前；响应失败发生在服务端返回之后，不等于撤销已提交操作，重试仍须保持同一幂等键。

## 覆盖与边界

请求覆盖 path（balances、按币余额、breakdown、查询/创建 deposit address）、query（entries、reservations、bookings、snapshots）、body（batch holders、raw journal entries、template journal、reservation、booking、preview、account reconcile），共 16 类入口。

响应覆盖 journal entries、entries 列表、各余额形状、batch 外层 holder 与内层 balances、reservation、booking/transition、deposit address/review、event、template preview、reconciliation details、snapshots。测试按公开方法验证 24 类响应形状。列表中的任意一行不安全时，整个 Promise reject，不返回已读取的前几行，也不改写或过滤 ID。

字段选择器只沿已声明 DTO 路径访问，不把 metadata、模板 amount map 的同名字段或 actor_id 当成 holder。它不是完整 DTO schema validator：缺失字段和其他字段类型维持原处理。未来新增 holder-bearing endpoint/DTO 时，需同步增加选择器和公开方法回归测试；不能仅更新 OpenAPI 就假定运行时校验自动扩展。

`docs/BREAKING.md` 已说明兼容范围及宿主迁移建议。新集成可将外部字符串身份权威映射为稳定的安全 ledger holder；不能用截断、取模、hash 或 `Number`/`parseInt` 压缩大 ID。已有大 int64 holder 应通过保持 int64 的宿主 Go backend 处理，或另行版本化 string-wire；不能静默重映射既有账户。本任务不声称支持完整 int64，也不引入大数 JSON 依赖。

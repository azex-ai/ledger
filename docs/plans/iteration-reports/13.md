## 重放兼容裁决

现有 `attestJournal` 对已存在的 key 只返回原 `auth_status`，不重新签名且不携带 digest/signature/key ID。直接对这个结果调用 `VerifyJournalAuth` 会错误拒绝合法重放。

按主控裁决，示例只在 **`StatusSigned` 且 digest、signature、key ID 全部为空** 时走兼容分支：在事务外用 `VerifiedBalanceReader` 验证模板涉及的两条余额维度。任何部分缺损仍走普通验签并拒绝。该检查覆盖整个历史，其他 unsigned / invalidly signed journal 也会导致保守拒绝；它不是精确的单笔 journal 验签查询 API。

事务内 `PostAuthorized` 继续负责同 key/payload 匹配与正常写入校验。事务外签名检查不代替当下余额、精度、政策或 reservation 状态检查。没有新增核心 API 或通过 SQL 查询 auth 材料的生产代码。

真实 PG 断言包括：

- full / partial 消费 20：signed journal，余额 100→80，普通 hold 60→0 / 40；持久化 discharge 的签名字段为空。
- 固定 `EffectiveAt` 与双 key 重放：同 journal UID，signer 不再调用，journal / entries / receipts / legs / checkpoints / rollup 行数不增加，金额与 hold 不变化；变更金额拒绝 `ErrConflict`。
- verified reserve 门槛：原 hold 未到期且未签名 discharge，余额 80 时新 reserve 21 拒绝且零写入，20 成功。
- signer unavailable、bad signature、empty signature、未配置 signing 四类失败：没有新增 charge 或 settlement，余额 100、hold 60、reservation active 均保持；恢复 signer 后同事件成功。
- full / partial settlement 超过原始 hold：charge 61 能通过余额 floor，但 settlement 拒绝；整个 callback 回滚，不返回虚假 journal receipt，余额/hold/状态与所有记录数量保持。
- 两个 partial event 分别 20 和 10，第二个重放后余额 70、hold 30、两条 settlement legs，不重复累加。
- 既有 unsigned journal / bad-signature journal 使普通余额为 81，但 `VerifiedBalance`、gated reserve 和 receipt replay 均拒绝；失败不增加记录，原 reservation 与普通 hold 不变化。
- 测试 signer/verifier 每次调用时通过独立连接读取本数据库 `pg_stat_activity`，断言没有其他打开的数据库事务。

## 边界与交接

- 没有调用新 `Capture` 门面；该普通事务门面不提供这个 journal 预签名流程。
- 不声称资金生命周期全部强签名，也不声称数据库与 provider / chain 原子提交。
- 事务内 unsigned discharge 使 verified gate 保守占用原始 hold 至 expiry；改为顶层独立 settlement 可签 discharge，但会失去与 charge 的同事务原子性，本例不作此替换。
- 宿主管理已提交事件的跨操作去重、可信 reservation 绑定和模板配置；此 private helper 不是任意客户端输入的通用资金 API。原始 journal 仍可绕过 reservation，因此所有竞争消费须统一走 reservation 流程。

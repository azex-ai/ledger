## Preview 真实 wire 修复

`server/handler_metadata.go:344` 的预览 handler 只遍历 `req.Amounts`；旧 SDK 将页面的 `{ holder_id, currency_uid, amount }` 原样序列化，金额没有进入服务端要求的 map。本轮保留页面简写输入，将它转换为 `{ holder_id, currency_uid, amounts: { amount } }`。标准多金额输入使用 `{ amounts: { gross: "100.00", fee: "2.50" } }`，完整保留所有 key 和 decimal 字符串。

同时传入 `amount` 和 `amounts` 时，即使二者金额相同也通过 Promise rejection 返回 `TypeError`，不发起 fetch，不静默覆盖任一输入。两种形式都缺少也在 fetch 前拒绝。标准 map、原参数及其引用均不被修改；测试使用冻结的参数和 map 验证这一点。

公开输入为 generated canonical body 与 single-amount adapter 的 union。TypeScript 普通 union 不保证阻止混合两种形式的所有结构赋值，因此互斥由运行时检查保证；报告不声称混合参数一定编译失败。保持现有 hooks 的类型适配不变，未扩大范围修改 hooks。

## 交给 Task 19 的兼容变化

1. `createBooking` / `transitionBooking` 的 metadata 值现在按真实 Go `map[string]string` 收紧。旧 exported `CreateBookingBody` / `TransitionBookingBody` 仍在 `types.ts` 中，但不再作为 client 方法的输入来源。外部把参数声明为这些旧 DTO、并保留 `Record<string, unknown>` metadata 的调用方，应改用 `Parameters<LedgerClient["createBooking"]>[0]` / `Parameters<LedgerClient["transitionBooking"]>[1]` 或对应生成输入，把 metadata 明确转换为字符串标签。不能依赖旧类型接受嵌套对象；服务端实际不接受它们。本轮按主审裁决不增加未经需要的兼容桥。
2. Preview 自定义金额字段应移入 `amounts` map；只保留已使用的单一 string `amount` 简写。数字 amount、完全缺少金额输入、任意扁平自定义金额 key 不再是有效新签名。混合两种形式会异步报错。wire 金额仍是 decimal string，没有引入 number 换算。
3. 合法输入的兼容扩展：journal event / actor / effective time，template journal metadata，classification lifecycle，journal type holder kind，booking transition source；booking channel_name 和 template line sort_order 按真实 schema 可选。

这些是 TypeScript 输入契约和必要的 preview 适配，不是通用运行时 DTO 校验器。JavaScript 调用方仍需遵循服务端校验；holder 的额外运行时 fail-closed 检查继续由 Task 6 负责。本轮没有新增 endpoint、改变账务语义或声称支持完整 int64。

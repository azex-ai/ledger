## 改动与账务边界

- `captureUsage` 正数路径直接调用 `svc.Capture`，传入 reservation UID、原事件 base key、`credits_spend` 模板和 Partial 标记，删除重复的手写 Settle / SettlePartial + ExecuteTemplate 事务。`conversion_quotes` 与宿主 metadata 被复制保留，helper 仅添加 `usage_event_id`，不传入 Capture 的三个保留字段。
- 零用量 final 仍走 `Release`，零用量 partial 拒绝；流结束仍 `FinalizeSettlement`。取消释放剩余 hold，不返还已经记账的费用。已有付费、计量、流式、取消、失效及报价变更语义保持。
- 本示例的 ordinary transaction Capture 使用 unsigned journal / discharge。调用者若在 `RunInTx` 内调用必须传播错误，并在组合其他金融操作时预锁完整并集；无 savepoint。宿主仍负责 provider 结果的持久不可变事件身份及原交易之外的外部调用。
- 账面示例：购入 1,000 CREDITS 后固定消费 25、计量消费 32.125，余额为 942.875；stream reserve 100 后分别 Capture 10 与 20，账面余额依次为 932.875 / 912.875，held 为 90 / 70，两步 `GetBalanceBreakdown.available` 均为 842.875。Finalize 后 held 归零，可用余额为 912.875。原币 USDC 为 0，各 journal 保持本币平衡，不跨币相加。

## Demo key 迁移

旧 helper 已使用 base+`:settle` / base+`:charge`，本轮保留这两个派生规则。真正的不兼容是旧 charge payload 缺少 Capture 新增的 `capture_mode` / `capture_template_code`。本例不修改既有 journal、不重命名已提交事件、不建议所有宿主更换业务 key。

新的固定 fixture namespace 为 `credits-demo-v3-capture`，仅用于新的独立示例数据库。`setup` / `scenario` 第一行检查是否存在其他 `credits-demo*` journal 或 reservation，有则返回 `ErrConflict`，避免换 namespace 后向旧库再做一轮充值/扣款。当前 v3 setup + scenario 可再次幂等运行。生产旧事件须由原处理版本或宿主明确的对账/迁移流程保留原身份处理。

主控明确保留原先的 `Migrate` bootstrap：它在 runtime role 建立前运行，不能为了此例破坏首次启动。Legacy guard 保证的是随后 demo 配置与账务写入被拒绝，不承诺没有 schema migration 变化；不支持两个 demo 版本并发运行于同一数据库。README 已写明这些边界。

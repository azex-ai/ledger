## 配置与经济效果

- 复用 `CurrencyInput`、`TemplateBundle`、`TemplateParams`、`FixedRate`，未增加配置 DSL、业务 package、数据库表或依赖。直接安装 `DepositBundle`、`FeeBundle`、`FXBundle`；POINTS 仅用已有类型配置 `points_issued` credit-normal 系统科目与两行发行模板，复用 debit-normal / available 的 `main_wallet`。
- 充值 100 USDC；通过四行 `fee_charge` 收取 25 USDC；按宿主 `catalog-v1` 固定比率将 1 USDC 换为 1,000 CREDITS；发行 100 POINTS；以 20 CREDITS 换 2 ROSE。费收 USDC 的选择经过主控确认，避免把 FX 发行的 credits 放入费用托管科目造成不必要的解释负担。
- 最终用户 wallet 为 74 USDC / 980 CREDITS / 100 POINTS / 2 ROSE，另有 25 USDC 的 memo `fee_expense`。系统分类逐项验收：USDC `custodial=75`、`fees=25`、`settlement=-1`；CREDITS `settlement=980`；ROSE `settlement=2`；POINTS `points_issued=100`。
- Fee 原模板是 DR user fee_expense / DR system custodial / CR user main_wallet / CR system fees。费用收入与 credits 消耗/赎回的对手科目减少不是同一语义。所有 NormalSide 与 BalanceRole 对照源码，并通过实际安装结果断言。
- 每次 Exchange 两币 journal 与 reservation 由现有原子门面完成；全过程共七笔 journal、两个已结算 reservation。按实际持久分录逐 journal / currency 检查 DR=CR，不把不同币种数量或 normal-side 科目余额混合相加称作守恒。
- 独立业务 oracle 使用上面的字面量预期，不用被验收的模板、rate 或 quote 再计算“正确”答案。主程序检查最终用户和系统分类余额，测试另验证 `GetBalanceBreakdown.available` 与全部 hold 为零；memo 不增加可用余额。

## 反例与重放

- 反向费用：从实际已安装的 `fee_charge` 克隆测试候选、反转全部 EntryType，经 `Render` 和实际 PostgreSQL 记账仍然平衡，却使用户 wallet 变为 125、expense 为 -25，系统 custodial 为 125、fees 为 -25。业务 oracle 要求 75 / +25 / 75 / +25，因此返回 `errEconomics`；测试将其传播出 `RunInTx`，验证 journal / reservation 数量和四项余额完全恢复。
- 错误 gift rate：把合法比率改成 0.5，使 20 CREDITS 输出 10 ROSE。Exchange 对给定 quote 的算术及双币入账正确，两笔 journal 各自平衡；但产品要求是 2 ROSE，独立 oracle 拒绝该候选。调用者事务传播错误并回滚两笔 journal 和 reservation，CREDITS / ROSE 的用户与系统余额、hold 以及持久行数均恢复。
- 正常完整场景重放相同 `configured-demo-v1` 事件 ID，复用原七个 journal UID，余额和 reservation 数量不变；对已完成 gift ID 改 rate 返回 `ErrConflict`，无额外效果。README 明确新版本只用于新事件，不能更换旧事件 ID 来绕过冲突。

## 宿主边界与交接

README 要求 fresh 专用 DB、分离 migration / runtime 凭证；测试另用可建临时 DB 的管理员连接，实际账务路径仍为 runtime role。充值与积分发行是可信本地 fixture。固定费用展示的是配置记账，raw `ExecuteTemplate` 不负责预留资金，生产并发收费需要宿主授权及原子 reservation / fee 组合；本例没有复制 Capture 等无关流程。

执行器在事件提交后检查最终效果，整个示例不是一笔事务，不能把最终验收失败说成自动撤销已提交事件。负面测试显式使用外层事务回滚候选。配置验收应在上线前完成，已提交状态沿用原 event ID / payload 恢复。原币数量、USD 展示估值、兑换与提现资格分离；POINTS / ROSE 是计量单位，不从定价或 available role 推导可兑现金的权利。

本轮没有产生新的全局规则或跨项目知识；项目特定裁决留在本报告及 README。主控后续负责独立 T2 review、完整集成 gate 和授权推送。

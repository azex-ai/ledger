输入为审计 R6 与 Phase 0 金额计算契约；输出为目标 exponent 校验、边界与算术回归、扩展 fuzz 输入。交由 root 做独立域评审、Codex 第二意见与串行集成；此报告记录精度裁决和验证证据。

## 精度裁决

复用现有 `MaxAmountWorkingFractionalDigits = 36`，不新增另一个任意精度常量：

| Helper | 允许的目标 exponent | 原因 |
|---|---|---|
| `Round` | `[-36, 36]` | 保留负数粗粒度舍入，以及超出 Currency 精度的中间计算 |
| `ConvertAt` | `[-36, 36]` | 与 `Round` 一致；在乘法前验证目标 |
| `Allocate` | `[0, 36]` | 保留既有非负约束，并允许工作精度下精确分配 |

36 已是金额 helper 输入的工作精度边界；Currency / 存储仍是 0..18。本轮限制的是计算资源，不将合法工作精度收紧为存储精度。负精度的输出沿用既有算术语义；helper 结果仍须通过记账入口的金额和币种精度检查，不能据此认定任何计算结果都可入账。

## 改动与验证

`core/money.go` 新增私有目标 exponent 校验，直接比较整数，避免对 `MinInt32` 取负溢出。三个入口在乘法、rescale、Truncate 或 Shift/BigInt 前返回 `ErrInvalidInput`。金额和权重的既有 magnitude 检查不变。

`core/money_exponent_test.go` 覆盖边界 ±36、首个越界 ±37、普通负精度的所有舍入模式及未知模式的既有回退、正负金额和零、int32 极值以及 ±1,000,000,000。36 位的 1/3 分配验证每份精确值、余数归属及总额守恒；ConvertAt 也验证工作精度和目标校验的错误优先级。极端目标只在修复后运行，未重复执行旧实现的大指数资源消耗。

`FuzzAllocateFromStrings` 不再跳过异常目标 exponent：现在断言其返回 `ErrInvalidInput`，并加入正常工作边界与异常目标种子。它继续保留成功结果的精确守恒断言。

- 修复前，`go test -race -timeout 2m ./core -run '^(TestRound|TestConvertAt|TestAllocate)_RejectsExponentOutsideWorkingRange$' -count=1`：三个测试均安全失败，有限 ±37 / 37 被错误接受；没有运行原版极值计算。
- 修复后，`go test -race -timeout 3m ./core -run 'Round|ConvertAt|Allocate' -count=1`：PASS（1.346s）。
- `go test -race -timeout 3m ./core -run 'AmountMagnitude|Money|FixedRate|ConversionQuote|FuzzAllocateFromStrings' -count=1`：PASS（1.240s）。
- `go vet ./core`：PASS。
- `go test -race -timeout 2m ./core -run '^$' -fuzz '^FuzzAllocateFromStrings$' -fuzztime=10s -parallel=2`：PASS（22,377 次执行，总耗时 12.306s）。
- `git diff --check`：PASS。

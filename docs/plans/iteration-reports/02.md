# 第 2 轮：冻结策略按币种判断净额

任务：Ledger20 Task 2 / bus #31，风险 T2。分支 `codex/ledger20-t02`；基线 `97e33362abd436c072114ab863079ac65a78fad1`。

输入为审计 R1 和 Phase 0 冻结契约；输出为冻结策略修复、真实 PostgreSQL 回归和 I-17 契约更新。交由 root 做独立域评审、Codex 第二意见与串行集成；本报告保留实现与验证证据。

## 改动

- `postgres/account_policy_enforce.go` 将 frozen 净额键从 `policy_id` 改为 `(policy_id, currency_id)`。同一 holder-wide 策略下的 USD 扣减不能被 PTS 增加抵消；同币种分类之间仍可按净额判断。错误消息使用发生扣减的实际 currency ID。
- `postgres/frozen_currency_test.go` 覆盖 USD −100 搭配 PTS +100 / +1,000，并交换两组分录顺序。四个 case 都要求 `ErrAccountFrozen`，确认用户与系统对手方两币种余额不变，且 journals、journal_entries、balance_checkpoints、rollup_queue 行数不变。解冻后相同 idempotency key 可以成功记账，验证拒绝没有留下部分结果。
- `postgres/account_policy_store_test.go` 将 pending 确认扩展为 currency-wide 与 holder-wide 冻结两种情况，确认 pending 清零、available 增加，后续扣减被拒且余额不变。
- `docs/INVARIANTS.md` I-17 明确按币种净额判断并链接回归测试。closed、min_balance 和策略优先级的实现保持原有语义。

## 验证

使用本任务套件的 PostgreSQL 17，`internal/postgrestest` 为每个 case 创建独立数据库。以下命令运行时将 `DATABASE_URL` 指向该临时服务。

1. 修复前运行 `go test -race -timeout 5m ./postgres -run '^TestLedgerStore_Frozen_CrossCurrencyCannotOffsetDecrease$' -count=1`：四个 case 全部失败于预期 `ErrAccountFrozen` 却返回 nil，确认测试能检出原缺陷。
2. 修复后运行 `go test -race -timeout 10m ./postgres -run 'Frozen|AccountPolicy|Pending' -count=1`：PASS（21.442s）。覆盖新增跨币种回归、两种冻结 pending 确认、既有 closed/min_balance/优先级以及相关并发策略测试。
3. `go vet ./postgres`：PASS。
4. `go test -timeout 2m ./core -run '^TestInvariantsDocIsOrderedAndGapless$' -count=1`：PASS（0.264s）。
5. `git diff --check`：PASS。
